# 决策 08：车辆生命周期与界面架构

> 状态：已讨论，待实现
>
> 背景：将模拟器从"单车硬编码展示"演进为"可作为实车替身的信号平台"。需要定义车辆从选择到运行到熄灭的完整生命周期，以及配套的三页面架构。

## 背景

当前 app 启动后直接加载硬编码的 AURA T6，30Hz tick 立即开始，文件传输 TLS 监听器自动启动。没有"选车"概念，没有电源状态，没有 MQTT/BLE，控制面板没有连接状态。

目标是让模拟器可以"扮演一辆真实车"：打开 → 选车 → 车启动 → 连 MQTT → 发蓝牙广播 → 手机可连接鉴权 → 车控可执行。

## 核心决策

### D8.1 单实例运行（方案 A）

一个 app 同时只跑一辆车。切车 = 卸载当前实例（停 tick、断 MQTT、停 BLE、dispose 3D 场景）+ 加载新实例。

- BLE peripheral 是独占的，一个蓝牙适配器同时广播多个车辆不现实
- MQTT 连接对应一个 T-Box 身份，多车 = 多身份同时连 broker，测试复杂度过高
- 资源开销低，不需要并发管理

### D8.2 三档电源状态

```
Sleep    — 车库选择前 / 刚加载，tick 不跑，MQTT 断开，高压功能禁用
Standby  — 小电瓶供电，tick 运行，MQTT 连接，高压功能禁用
Ready    — 高压闭合，全部功能解锁
```

- 选车 → 自动进入 `Standby`（小电瓶自动有电）
- 用户手动"上电" → `Standby` → `Ready`
- 用户手动"熄火" → `Ready`/`Standby` → `Sleep`
- `Sleep` 后留在爱车页熄屏状态，可重新上电；切换车型才回车库
- 留好小电瓶和高压的扩展，后续可细化为 KL15/KL30

### D8.3 电源状态与服务映射

| 状态 | tick 循环 | MQTT | BLE 广播 | 文件传输 | 高压功能 |
|---|---|---|---|---|---|
| Sleep | 停止 | 断开 | 取决于 BLE 开关 | 关闭 | 禁用 |
| Standby | 运行 | 连接 | 取决于 BLE 开关 | 监听中 | 禁用 |
| Ready | 运行 | 连接 | 取决于 BLE 开关 | 监听中 | 解锁 |

**关键规则：**
- MQTT、tick、文件传输跟小电瓶走，Standby 启动
- BLE 广播有独立开关，默认关闭，跟电源状态解耦
- 高压功能（空调制冷、行驶、充电）在 Ready 才解锁

### D8.4 BLE 广播独立开关

- 默认关闭，用户需要测试 BLE 场景时手动打开
- 放在控制面板"连接状态"分组内
- 切换实例/回车库时重置为关闭
- BLE 广播开着后，不论电源状态（Sleep/Standby/Ready）都持续广播
- BLE 连接和鉴权不受熄火影响

### D8.5 熄火行为

- **MQTT 指令执行中**：等当前指令完成再进入 Sleep（门到位后再断电）
- **BLE 连接**：不受熄火影响，手机连接保持
- 熄火后留在爱车页，3D 场景进入熄屏/暗化状态，"上电"按钮重新可用

### D8.6 电源状态 interlock

- **Standby → Ready（上电）**：无前置条件，一键上电
- **Ready → Sleep（熄火）**：只检查不在行驶状态，行驶中提示"请先停止行驶"
- 后续可按需扩展（如档位检查）

### D8.7 三页面架构

三个平级 tab，共享 canvas，切页时重建场景。

| 页面 | 定位 | 内容 | 后台服务 |
|---|---|---|---|
| 欢迎（首页） | 展厅 | 3D 展示 + 滚动拆解 + 细节查看 + 颜色切换 | 无 |
| 我的爱车 | 驾驶舱 | 3D + 控制面板（6 组）+ 文件传输 + 电源控件 | 有（取决于电源状态） |
| 我的车库 | 选车创建 | 车辆实例卡片列表 + 创建入口 | 无 |

- App 启动默认进爱车页，加载上次选中的实例
- 无实例记录时爱车页显示空状态："还没有车辆，去车库选一辆"
- 车库选完实例后跳转爱车页

### D8.8 欢迎页 vs 爱车页

- **欢迎页**：当前的"看车"体验保留（3D 展示、滚动拆解、细节查看、颜色切换），但**无控制面板**、无后台服务。展厅模式。
- **爱车页**：3D + 控制面板，车辆实例已加载，SignalModel 在跑（取决于电源状态），MQTT/BLE/文件传输按电源状态运行。用车模式。

### D8.9 配置体系：模板 + 实例分离

- **模板**：`profiles/templates/`，应用打包内置，描述车型定义（门数、窗数、有无天窗、3D 模型路径、BLE/MQTT 参数模板）。如 `aura-t6.toml`。
- **实例**：`profiles/instances/`，用户创建，引用模板名 + 填充具体信息（VIN、车辆名称等）。如 `my-aura-001.json`。
- 同一模板可创建多个实例（两台 AURA T6，不同 VIN）
- 车库显示实例列表，不显示模板

### D8.10 车辆创建流程

1. 车库页点"添加车辆"
2. 展示可用模板列表
3. 选一个模板
4. 填写必要信息（VIN 等向车管后台申请过的信息）
5. 生成实例文件存到 `profiles/instances/`
6. 车库列表刷新

### D8.11 电源控件位置

- header 级全局控件，显示当前状态（Sleep/Standby/Ready）
- "上电"/"熄火"按钮
- 不放在控制面板折叠组内

### D8.12 控制面板灰显规则

| 状态 | 控制面板行为 |
|---|---|
| Sleep | 全部禁用，只有 header 的"上电"按钮可点 |
| Standby | 灯光/锁/门/窗/尾门可用；空调制冷/行驶/充电禁用（高压功能） |
| Ready | 全部解锁 |

### D8.13 连接状态展示

- **header 指示灯**：MQTT ● / BLE ●，绿/灰/红三色，只读，扫一眼知道状态
- **控制面板第一组"连接状态"**：展开显示详情（MQTT broker 地址、连接耗时、BLE 广播名、BLE 开关、文件传输状态）
- BLE 广播开关在此分组内

### D8.14 爱车页控制面板分组（6 组）

1. 连接状态（MQTT 状态、BLE 广播开关、文件传输状态）
2. 车门与锁
3. 车窗与天窗
4. 电动后备箱
5. 灯光
6. 空调与充电

### D8.15 启动全流程

```
App 启动
  → 读上次选中的实例
    ├─ 有记录 → 加载实例 → 进入爱车页
    └─ 无记录 → 进入爱车页（空状态）→ 用户去车库选车

加载实例：
  1. 读实例 JSON + 对应模板 TOML
  2. SignalModel 初始化
  3. 3D 场景加载对应 GLB
  4. power_state = Standby
     ├─ tick 循环开始（30Hz）
     ├─ MQTT 连接发起
     └─ 文件传输 TLS 监听器启动
  5. BLE 广播 = 关闭（用户手动开）
  6. 进入爱车页

用户"上电"：Standby → Ready（高压闭合，解锁行驶/空调/充电）
用户"熄火"：Ready/Standby → Sleep（等指令完成，留爱车页熄屏）
用户"切换车型"：→ 熄火当前 → 回车库 → 选新车 → 加载
```

### D8.16 实例启动后 3D 场景资源处理

共享一个 canvas 和 WebGLRenderer，切页时 dispose 旧场景 + build 新场景。GLB 已在内存中（Three.js CacheLoader），重建场景快。
