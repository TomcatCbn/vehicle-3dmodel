# 决策 20 — 开场增加车头 Logo 特写可切换运镜

## 背景

决策 19 已将后段运镜精简为尾灯特写后直接回整车，解决绕车两侧造成的晃动。用户希望保留该直回版本，同时再尝试一条“尾灯特写 → 车头 Logo 贴近特写 → 拉远回展台视角”的路线，并能在页面中切换比较。

## 选项

### A. 单侧弧线接近车头（采用）

尾灯特写后只沿车身一侧运动到车头 VW 标，短暂停留后拉远回整车。不绕到另一侧，路线连续且没有往返，是三种方案中运镜最短的一版。

### B. 高位跨越车顶

先拉高相机，再越过车顶接近车头。水平转向较少，但增加明显上下起伏，不符合减弱晃动的目标。

### C. 先拉远再靠近车头

尾灯后先回远景，再单独推进车头特写。构图更稳，但增加一次远近往返，整体运镜更长。

## 结论

采用 A，并保留决策 19 的直回轨迹作为另一可选版本：

- 默认播放 `front-logo`：前段大弧转入和尾灯慢动作特写保持不变；尾灯后沿单侧弧线到车头 VW 标，贴近并短暂停留，再平滑拉远到 `home`。
- 欢迎页在重播开场按钮附近增加“直回 / 车头特写”运镜选择，复用现有按钮组样式和同一动画循环。选择作用于下一次播放，不改动车辆信号。
- 两版共用车辆行驶路线、车轮运动、时间重映射、10 秒实际时长和最终机位；`entrancePose` 通过显式变体参数选择相机与注视点轨迹，避免复制车辆运动逻辑。
- `front-logo` 为默认离线导出版本，重新生成 `public/models/entrance-poses.json`；直回版继续由同一导出脚本按需生成，不新增长期重复数据源。

## 影响与验证

- 运镜测试同时覆盖两版：直回版保持决策 19 的回归断言；车头版检查单侧接近、车头 Logo 特写、最终回位、镜头连续性、防穿插和安全距离。
- UI 契约测试检查两个运镜按钮、默认选中态和可访问名称；切换只影响开场配置。
- 更新 README 的开场流程、切换操作和离线导出说明。
- 运行 `npm test`、`npm run build`、`git diff --check`，并在浏览器分别重播两版，核对运镜、最终取景和交互恢复。
