# 决策 21 — 欢迎页增加车辆展示与车端模拟探索面板

## 背景

欢迎页隐藏爱车页的车辆控制台，车辆完成进场后，桌面右侧形成较大留白。用户希望补充内容，但页面必须同时体现两个核心用途：可交互的三维车辆展示，以及供开发、测试和演示使用的车辆信号模拟，而不是单纯堆砌宣传参数。

## 选项

### A. 展示与模拟工作流导航（采用）

以“一台展车，一个可测试的车端”为核心表达，提供进入车控台、细节与结构演示、行驶场景演示三个现有功能入口。主入口突出车控与状态联动，次级入口保持轻量分隔线样式。

### B. 车辆参数与品牌海报

展示车色、部件数量或宣传文案。视觉干扰较少，但不能有效引导开发、测试和演示工作流，也容易引入未经核实的续航、功率等车辆参数。

### C. 实时车辆状态面板

复制爱车页的电源、连接和车控状态。信息密度较高，但会与现有控制台重复，并可能让欢迎页的独立展示状态与真实后端状态产生混淆。

## 结论

采用 A：

- 桌面端在右侧增加探索面板，车辆进场期间随现有欢迎页界面隐藏，停稳后恢复；减少动态效果偏好下直接显示。
- 主按钮切换至爱车页；细节与行驶按钮复用 `data-inspect-open`、`data-drive-open` 及现有弹窗、状态校验和焦点恢复，不建立新的状态副本。
- 欢迎页底部移除重复的细节与行驶入口，保留视角、运镜、重播和文件传输等场景工具。
- 手机端将面板压缩为车控、细节、行驶三个并列入口，并缩短欢迎页首段高度，避免为已隐藏的控制台保留空白。
- 文案仅描述三维展示、本地信号模拟和交互验证，不将 BLE / MQTT 描述为已完成真实协议联调。

## 影响与验证

- 修改欢迎页 HTML、样式和页面路由事件，补充 UI 契约测试与 README 交互说明。
- 运行 `npm test`、`npm run build` 和 `git diff --check`。
- 在 `1280×900`、`390×844` 视口核对车辆主体、右侧面板及移动端入口，验证车控页切换、细节弹窗、行驶弹窗和重播进场时的显隐与焦点恢复。
